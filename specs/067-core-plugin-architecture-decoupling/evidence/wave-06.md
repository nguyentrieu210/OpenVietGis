# Wave 06 — durable configuration change replay

- Core migration 0050 installs an append-only module configuration invalidation stream per organization/project. Activation, permission-policy and binding-set row changes trigger event capture inside the same transaction. A per-project stream row serializes sequence assignment through commit; rollback leaves no event or gap. Runtime can read through RLS but cannot write the event tables directly. Event payload only contains module key, kind and sequence.
- Rust API GET /extensions/change-events verifies unrestricted project scope on every request, returns bounded pages with epoch/sequence cursor, and requires a fresh snapshot on initial connection, incompatible epoch, future cursor or missing sequence. Cursor is string-valued to avoid JS integer precision loss.
- One bounded replay loop per authorized browser project consumes changes at a five-second cadence, coalesces duplicate hints and refreshes activation before delivery. Network failures retain the cursor and back off; online resumes; existing 30-second refresh remains fallback. API authorization remains authoritative. This is durable HTTP polling, not WebSocket push; there is no automatic retention or cross-restart cursor persistence, and a full restore procedure must reset stream epoch before accepting new writes.
- Verified PostgreSQL fixture: transaction rollback, concurrent commit ordering, page boundaries, all three event kinds, RLS isolation, no permission payload, runtime trigger write and guarded downgrade. SDK tests 6/6, browser mock remote revocation/restoration without focus event (Core map/canvas stable, two feature requests), Rust API cargo check, TypeScript and 13 architecture tests passed.
