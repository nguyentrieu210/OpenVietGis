# Wave 05 — resident plugin fleet and local invalidation contract

- Each compatible activated module has an independent keyed runtime instance (extension/version/activation/revision). Selecting Core or another plugin does not unmount a resident hook. Disabling or replacing an activation removes its instance; stale snapshots are pruned. Error boundaries isolate module failures. Core retains the map and canvas.
- Global map filters, labels, styles, panels, toolbar and search belong to one foreground module at a time. Background host map mutations and new host actions are blocked; old foreground callbacks cannot become active again on later selection. Search generations discard results from superseded plugin selections or permission revocation. The SDK is for trusted compiled modules, not a sandbox: direct module API access still requires server authorization. Modal child component state is not guaranteed to survive switching.
- Added typed local client-instance/organization/project/module invalidation hints for committed permissions, bindings and activation writes. HN subscribes and rereads authoritative policy/bindings without requiring window focus. No private payloads in hints. Cross-device durability, server outbox/reconnect and full event sequencing remain open.
- Verified two independent sample modules in SDK browser fixture: state retention, foreground ownership, rejected background actions, isolated error, cleanup and stable Core DOM. Real HN browser smoke (mock API) passed switching to Core and back retaining open area navigator, binding, revocation and removal; two initial feature requests. SDK invalidation tests 3/3, TypeScript Core, 13 architecture tests and diff check passed.
- E02/E05/E09/E10/E11/E14 advanced. Only HN is a shipped frontend business plugin; second module is a fixture, not a claim of production land-asset runtime. No simultaneous global filter composition, server durable events, full draft/undo acceptance or live deployment. Wave 04 pure-command HTTP test remains outstanding.
