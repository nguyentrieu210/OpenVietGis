# Command broker
Proposed logical request: command_id, release_digest, project_id, resource_ids, typed input, expected_revision, idempotency_key. Actor/org come from authenticated server context, not trusted body. Validate active installation, signature/revocation, capability, current grant, resource ownership, schema, consent class and quota before dispatch. Async jobs carry scoped service grant and recheck at execution/output. Response: operation_id, status, typed output or job_id, revision, provenance, audit_ref. Errors stable: INVALID_INPUT, UNAUTHORIZED (401), FORBIDDEN (403), NOT_FOUND (404 without resource leak), CONFLICT (409), INCOMPATIBLE (422), QUOTA (429), UNAVAILABLE (503). Idempotent retries return recorded receipt, mismatched payload conflicts. Cancel and unsubscribe on scope switch/revoke. No raw SQL, arbitrary network, tokens or device handles exposed. Read-only vs mutation vs publish explicitly distinguished.
