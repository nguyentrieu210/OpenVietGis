# Commercial profile
Payment provider adapter sandbox only until approval. Hosted checkout, no card secrets in Core. Verify webhook signature and timestamp using provider contract; deduplicate provider/event ID, transactional ledger + outbox, reconcile against provider records. Use ISO currency and integer minor units, immutable balanced ledger, reversals for refund/chargeback, settlement/payout reports and reconciliation. Entitlement state trial/active/grace/expired/revoked with policy expiry; independent data permissions. Publisher revenue split, tax and refund rules configurable and reviewed before live. Failed/replayed events never duplicate activation or payout. Private/self-host grants signed by trusted authority. Store billing policy and legal/license review gate per platform.

### Persistent sandbox preview
Migration 0055 introduces immutable sandbox orders and signed event/ledger receipts, scoped by organization with forced RLS. The existing human organization owner/admin transaction locks the organization and membership; order identity is idempotent and events are unique by organization/provider event ID. Store exact event payload, canonical signature, calculated postings and timestamp in the same transaction. Rebuild and verify the projection from persisted signed events on reads and writes; a mismatch fails closed. No card fields, checkout provider, payout or production entitlement is involved. The sandbox quote is administrator-selected synthetic data, NOT a real sale price; the exact release digest must be reviewed. The sandbox license state is not consulted by the plugin runtime.
Routes under /api/v1/organizations/{organization_id}/marketplace/sandbox/orders: POST {quote,release_digest}; GET /{order_id}; POST /{order_id}/events {event,signature}. Event submissions are authenticated administrator simulations with CSRF, not public provider webhooks. Configure a dedicated sandbox Ed25519 public key via OPENVIETGIS_PLUGIN_SANDBOX_PAYMENT_PUBLIC_KEY; no key means all routes are disabled. Do not reuse the catalog operator key. Rotating sandbox keys without a historical trust-key migration will make old events unverifiable.
The SDK offline lease verifier checks a distinct authority's signed domain openvietgis.entitlement.lease.v1, exact issuer/organization/subject/device/project/manifest/release, epoch, revocation IDs, expiry and last trusted time, maximum 24-hour duration. The host must supply authenticated trusted time and revocation state. This verifier is not a lease issuer, device security mechanism or permission grant. Offline runtime remains disabled.

### Authority-issued online commercial licenses (Wave 0 preview)
The root-signed global trust policy may include an additive commercial object: audience (installation identifier), authority_key_id (SHA-256 of an independent Ed25519 public key), and sorted cumulative licensed_release_digests. Empty/absent commercial policy preserves the pre-existing free V2 catalog contract. Once a checkpoint includes licensed releases, later policies cannot remove their classification or change audience. New versions require explicit classification by the root authority. The operator/root/publisher/sandbox keys cannot act as license authority. Configure OPENVIETGIS_PLUGIN_LICENSE_PUBLIC_KEY; a missing/mismatched key fails closed for restricted releases.
The signed license schema openvietgis.license.grant.v1 binds audience, authority fingerprint, grant UUID, organization UUID, extension key, exact release digest, monotonic sequence, kind (trial/subscription/revoked), issued_at, valid_from, valid_until and grace_until. Trial max 30 days, no grace, only one trial per organization/extension across versions and no trial after any prior grant. Subscription max 366 days and optional grace max seven days; expiry boundaries exclusive. A new certificate supersedes the prior one immediately, including a future-start certificate (pending). Revocation certificate has equal issued/start/end/grace timestamps and supersedes prior grant. Authority rotation requires reissue and sequence advancement; certificates under previous authority fail closed. No automatic renewal or charging. Grant signing is offline with license_sign.py; use whole-second UTC timestamps and private key kept off API.
Migration 0061 adds immutable tenant-scoped certificates and unique sequence/grant IDs. Human organization owner/admin imports signed JSON via POST /organizations/{organization_id}/marketplace/v2/licenses, checks GET /{release_digest}. Server re-verifies current signature and persisted digest on access. All restricted dependencies must have an allowed state before Web V2 document, approval, invocation or processing confirmation; license does not confer data permission or activate an extension. Unrestricted free releases are unchanged. Sandbox commerce cannot issue these grants. UI shows V2 license-required indicator and certificate import/status for organization admins.
This is an online certificate authorization layer, not production payment service. A tenant revocation becomes effective when its signed certificate is imported; no independent central push/webhook yet, so do not rely on voluntary import for urgent revocation. Root-signed global release revocation remains available. V1 iframe/runtime is outside this commercial gate, so no claim of exclusive monetization until V1 policy convergence. Native offline lease issuance requires authenticated device enrollment, trusted clock/revocation distribution and qualified transport and is NOT enabled.

### Signed quote preview and reconciliation (sandbox)
The independent price authority signs openvietgis.checkout.sandbox.offer.v1 with audience, release digest, publisher identity, exact Quote (organization/order/currency/price/tax/publisher share/access expiry), issuance and expiration. Quote currency allowlist VND/USD/EUR; max 30-minute quote validity and 366-day access term. POST /organizations/{organization_id}/marketplace/sandbox/offers/preview accepts {offer,signature}, requires configured OPENVIETGIS_PLUGIN_SANDBOX_OFFER_PUBLIC_KEY and OPENVIETGIS_PLUGIN_SANDBOX_OFFER_AUDIENCE, existing sandbox provider key, human org-admin session and CSRF; verifies catalog/release/publisher identity and price signature. Returns checkout_created:false. This is read-only verification, not durable order binding or provider checkout. Existing synthetic order creation is unchanged.
GET /organizations/{organization_id}/marketplace/sandbox/orders/{order_id}/settlement replays verified stored ledger events and computes exact minor-unit clearing, publisher payable, platform revenue and tax payable plus ordered event receipt digest. Every receipt must balance, event IDs must be distinct, aggregate amounts nonnegative and balanced, clearing must match outstanding ledger balance. POST /reconcile compares an unverified manually supplied statement with the same report and explicitly returns statement_verified:false. POST /reconcile-signed accepts {statement,signature} over openvietgis.settlement.sandbox.statement.v1 with exact org/order, observed_at and report; the pinned sandbox payment key authenticates the statement and freshness (five minutes old max, 30 seconds future max). Both comparison endpoints are diagnostic only, do not mutate balances, and do not create financial settlement or payment authority. SDK exposes all four APIs.

### Durable sandbox checkout acceptance
POST /organizations/{organization_id}/marketplace/sandbox/offers/accept accepts the same signed offer as preview, rechecks the catalog, dedicated authority, human organization admin and CSRF, and records an immutable sandbox order. No external provider session is created. Order identity is the signed quote order UUID. Existing 0055 quote JSON column supports a versioned openvietgis.sandbox.accepted-offer.v1 record holding the exact signed offer, offer digest, signature and historical authority public key. No parallel order table or new migration. Legacy plain Quote rows remain readable; a signed order cannot be replaced by a plain quote or by a different signed offer with the same order ID. The database clock is sampled after obtaining the organization lock; the signed offer must still be valid. Exact duplicate acceptance within the validity window returns the same order with replayed:true. After offer expiry use the existing order snapshot rather than attempting re-acceptance. Historical signed offers are reverified at the immutable recorded creation timestamp, using the historical signing key snapshot in the trusted database. This is not independent protection against compromise of the trusted database.
The existing authenticated sandbox event submission route continues to require the separate provider signature. For accepted offers, events cannot predate order creation, and capture must occur strictly before the signed offer expiry. Existing ledger checks enforce exact order/currency/amount and idempotency; refunds remain available after expiry. Snapshot includes nullable checkout_offer_digest and checkout_expires_at. This is only a synthetic checkout reservation and ledger integration; external payment sessions, public webhook ingestion and transactional outbox remain unimplemented. Existing unsigned synthetic test order endpoint is not a paid checkout. Do not deploy older binaries concurrently with the new quote encoding: they cannot read accepted-offer rows. No migration or downgrade of the immutable accounting evidence is attempted.
