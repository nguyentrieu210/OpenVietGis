# Host and SDK
One canonical command and schema identity; generated clients Rust, TypeScript, Dart, Python, REST, realtime, MCP, declarative and optional WASM/native bridge. Contributions bind exact manifest/release and platform. Web/desktop/mobile declare slots and capabilities; native mobile no dynamic Dart/native download, no arbitrary WebView bridge; unsupported commands hidden/disabled with reason. Signed manifest v1 compatibility unchanged; v2 separate envelope, deterministic canonical JSON signature golden vectors; operator release approval signature separate. Schema validation before render, proposed <=256KiB envelope, <=500 nodes/depth16, <=32 actions, <=10MiB total assets, queue 8/action timeout30s configurable lower by host. Data files independent of plugin entitlement. SDK semver/deprecation and adapter tests; no separate identity or registry.

### Shared runtime wire contract (slice 16)
The current Web response profile remains web_read_only. The transport-neutral TypeScript parser and buildPluginV2Invocation are reusable by the future Desktop managed host; Web SDK invocation now uses that builder. The Dart UniversalRuntime/UniversalPin parser and UniversalSession.fromRuntime candidate use the same manifest/release/activation/lock/catalog/grant snapshot and exact invocation body. Grant revisions are canonical decimal signed-64-bit strings; a granted runtime cannot have zero grant revision. Parsers validate root identity, unique dependency keys and permissions, known read-only actions, argument shape and payload limits. The trusted native host callback receives only scoped typed body, never a plugin-selected URL or credential. Native processing documents can be parsed but UniversalSession explicitly denies their dispatch until its confirmation adapter is qualified. Native scope changes, including grant revision changes, invalidate the session. These checks do not replace server-side grant/ACL checks, signed catalog verification or device enrollment.
Synthetic cross-language vectors fixtures/spec075/runtime-wire-vectors.json are generated from the four existing reference documents by tests/spec075/generate_runtime_vectors.py. They include four valid runtime/request pairs and eight invalid runtime envelopes. These are wire fixtures, not signed entitlements, authentic session records or proof of executable geometry. Rust reads the four valid invocation bodies and validates document/command policy; TypeScript checks all twelve cases; Dart tests are provided but not yet executed.
