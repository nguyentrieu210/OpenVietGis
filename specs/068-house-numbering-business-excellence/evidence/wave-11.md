# Wave 11 — approval input pinning and reconciliation quality gate

- New module migration hn_0013_proposal_pins adds append-only, tenant-scoped submission evidence, keyed by proposal and submitted revision. Stores submitting actor and SHA-256 digest only, not raw survey attributes or private household values. No backfill pretending historical approval inputs are known. Legacy submitted proposals without pins must be withdrawn and resubmitted; existing approved proposals are untouched.
- Submit records the digest after number transition in the same transaction. Approval independently verifies eligible buildings, confirmed routes, authoritative rule, unchanged submitted numbers and the current digest. Digest includes building, route, number and rule revisions, resolved route geometry, linked feature content and associated evidence/reconciliation case revisions. Core feature/source share locks are acquired before reading inputs. Unresolved non-matched reconciliation cases block approval. Removed redundant pre-lock item validation and route lock.
- The proposal author and submitting actor cannot approve their own proposal. Withdrawal/rejection preserve the old pin and resubmission creates a new revision. This is a conservative workflow decision, not a claim of a legally valid certificate or completed field reconciliation.
- Added isolated PostGIS/HTTP acceptance harness and optional exact-SQL-only mode. Python syntax and diff checks passed; architecture checker passed before test harness changes. Rust check reached checking the application after storage and HTTP crates, but the final check did not return success. VPS concurrent Rust jobs exhausted RAM/swap; full new binary build, migration/SQL execution and HTTP acceptance not verified in this wave. Do not release until these gates pass. The legacy Python adapter is not yet aligned with the new approval behavior.
- E10/E11 advanced, not complete. Full evidence acceptance, approval UI, certificate/plate lifecycle, real data, parity and concurrency regression remain open. No production migration, merge or deployment.
