# Wave 16 — durable offline survey outbox and receipt protocol

- Replaced the survey panel's project-wide localStorage queue with per-row IndexedDB transactions, keyed by authenticated actor, organization and project. Drafts contain client UUID, building revision, observation, GPS accuracy and optional File. Browser commits the draft before reporting saved, preserves the photo bytes until survey acknowledgement, and uploads the photo before syncing. The old unowned localStorage queue is not deleted or automatically attributed to a different account; the UI warns of its existence. No server migration required.
- Optional receipt_version=2 preserves the existing v1 request and response shape when omitted. V2 verifies the authenticated queue actor, unique client UUID per batch, required positive building revision and building identity. Existing committed payload replay returns the exact client UUID/survey ID acknowledgement; changed payload remains a conflict. New operations lock the building and reject stale/inactive versions or an already accepted survey. The v2 fingerprint includes actor, protocol and expected building revision; v1 fingerprints remain compatible.
- Browser sync is bounded to batches of 50, verifies identity before sync and photo upload, uses Web Locks to serialize tabs, and refuses sync on browsers without Web Locks. It removes only explicitly acknowledged sent rows, retains conflict and unknown rows, displays conflict codes, and never auto-resubmits conflicts. IndexedDB is durable browser-local storage, not an encrypted vault or a server backup; users need a verified online session and loaded buildings before going offline. The currently open panel supports offline capture; full offline cold launch, account-recovery migration of legacy queue, explicit conflict-resolution/rework workflow and retention policies remain open.
- Real Chromium smoke passed two-tab concurrent insert, reload with photo bytes, offline enqueue, per-row deletion and account isolation. Three receipt/key unit tests passed; Rust module HTTP compile, module TypeScript, Python syntax, architecture 18/18 and diff checks passed. New disposable PostGIS HTTP acceptance harness covers mixed acknowledgement/conflict, exact replay, altered payload, actor mismatch, duplicate request IDs, accepted building and changed building version. Harness not run on a rebuilt binary. Photo upload currently lacks an idempotent receipt if its response is lost before the artifact ID is saved, so orphan photo uploads are possible; local photo is retained and survey UUID remains idempotent.
