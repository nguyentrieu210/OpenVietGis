## T003 proposed commit-order protocol
Acquire existing org -> project locks before source mutations, including internal worker/service paths; verify every path in integration tests before implementation approval. Maintain one project counter row, increment under transaction lock; append minimal internal event in same transaction as R006 changeset, preferably a reviewed database trigger on INSERT (operations visible after commit) or repository hook before commit. Do not increment sequence outside transaction. If other mutations do not respect lock ordering, fail gate and unify lock order; avoid lock inversion. Rollback removes both event and counter advance. Notification remains wake-up only. Reads under shared project lock pin high-watermark with authorized source snapshot. Paginate by immutable cursor, advance over filtered events without leaking hidden IDs; do not infer gaps from missing visible IDs. Coalesce changed IDs against current authorized state; if visibility cannot safely be proven, emit reset without IDs. Access epoch changes invalidate cursors; membership/rule/service revocation must be audited for coverage. Schema/catalog changes can reset only affected accessible scope or whole cache when necessary. Cursor retention floor and scope/epoch binding tested separately. No raw audit before/after delivered. Decision proposed, real DB concurrency proof pending.
## T004 desktop human auth decision
ADR-013 and security.py: OIDC external identity maps to first-party human session cookie. Existing generic Bearer path accepts service credentials only. OIDC provider uses S256 PKCE for web login; that does not establish native QGIS auth support. Prefer first-party desktop pairing using existing authenticated browser: random verifier, S256 challenge, short-lived one-use grant, user-visible organization/project/device and approval; redeem over TLS with verifier and bind new hashed opaque credential to human actor/session, not service identity. New dedicated token prefix and scoped managed auth adapter, no accepting raw provider access tokens or copying browser cookies. Grant expiry, replay rejection, CSRF on browser approval, exact redirect/origin if loopback used, rate limits and token redaction. Use current membership/ACL on each request and stream heartbeat. Logout/revocation semantics explicitly tested. Live auth and threat-model review pending.
## T002 native provider gate
Current QGIS plugin uses afterCommitChanges; too late to enforce server-first save. Spike uses native memory provider with beforeCommitChanges and setAllowCommit(False) to test rejection preserves draft; test accepted case separately. This is an experiment, NOT a production provider. For a failed server receipt, keep managed state pending/denied and never accept local commit; for accepted receipt but local apply failure, recover from server receipt and bootstrap, never resend new operation ID. For native paths that bypass the verified interception, choose explicit managed Save command on read-only canonical layer, separate staging layer. Native Windows/Linux tests must prove UI, undo, multi-layer editing and real network error behavior. No PyQGIS on VPS; spike cannot run here.
