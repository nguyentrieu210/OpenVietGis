# Data model / invariants
Existing schema is authoritative until catalog and migration inventory is extracted. Logical concepts: Organization owns Workspace/Project; Project scopes Layer and DataSource; Feature has stable ID, geometry/CRS, attributes and revision; ChangeSet/ChangeEvent records actor, prior revision, scope and sequence; Cursor represents authorized stream progress; Job has scoped input/output and state; ModuleInstallation has scoped manifest/version/capabilities. TileCacheKey includes tenant/resource, authorization version, style/filter, tile coordinates and data revision as appropriate.
No new physical tables assumed. Change and outbox must commit atomically; consumers idempotent; cursor gaps trigger authorized snapshot recovery. Preserve constraints, indexes, RLS, identifiers and attribution. Additive schema only until rollback gate; verify canonical counts and deterministic hashes on staging restore.
