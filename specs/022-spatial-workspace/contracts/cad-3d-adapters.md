# R012-A / R004-B adapter candidate
CAD: the verified OCS deployed web automation docs explicitly restrict embed messaging to same origin. A project host must use a reviewed, pinned, isolated-origin CAD build and a trusted relay; do not proxy arbitrary remote HTML/scripts into the authenticated GIS origin. Upstream deployed HTML includes an external analytics script; production embedding is unavailable until assets are reviewed, external code removed/blocked, scoped authorization and versioned save API implemented. No protected project bytes or tokens go to remote CAD now. Existing R012 inspect/import/export endpoints remain the authorized integration path for already georeferenced 2D DXF.
Local georeference preview: require >=3 control points, explicit projected metre CRS, drawing units, declared residual tolerance and scale deviation. Fit nonreflecting 2D similarity; check all control residuals, reject degenerate configurations and implausible scale. Preview only; no DB publishing. Server must independently verify CRS definition and controls/transform and create versioned derived resource before a project can publish.
3D V1: actual MapLibre fill-extrusion, separate map surface (host configures existing pinned MapLibre worker URL before loading), use authorized WGS84 2D polygon footprints and explicit nonnegative base/height in metres above a flat reference surface. No invented heights, no terrain/vertical datum claim. Input bounds and data validated; no external network by default. Existing GIS camera and selection are host-owned. Rendering of a synthetic fixture is not production cross-tenant acceptance. Cesium/glTF/terrain follow an independent gate.
