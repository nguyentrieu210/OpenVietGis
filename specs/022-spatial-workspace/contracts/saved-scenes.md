# Named project 3D scene definitions (T016)

## Requirement and plan
Users with project read may browse and reopen a named scene; project editors may capture the actual 3D camera, model version pins, DEM reference, GIS height field and layer visibility as a new scene or new immutable scene version. Multiple users can work without silently overwriting one another. Sharing is through existing project membership (no public link or cross-project access).

- Constitution check: reusable core, additive scoped schema, immutable versions/actor/audit, CSRF/project edit for writes, authenticated unrestricted human/project read for reads, exact CRS 4326 camera with explicit lon/lat, zoom, bearing and pitch, no inferred vertical conversions. Portable scene profile JSON and existing model file downloads; no duplicate binary or external data flow.
- Storage: `spatial.scene_versions` composite organization/project/scene/version key, RLS forced, runtime SELECT+INSERT only. Up to 100 scenes per project and 50 versions per scene. Project advisory transaction lock serializes quota/version guard. Revision uses expected_version and 409 on stale writes.
- API `/api/v1/organizations/{org}/projects/{project}/3d/scenes`: GET latest catalog; POST create; GET `/{id}/versions` history; POST same path new version; GET `/{id}/versions/{v}` returns scene plus exactly pinned model placement records. Model byte SHA-256 rechecked on download. A model may have only one version per scene; max 8 models and existing client 250k triangles budget.
- Profile: name; model id/version/visible; optional DEM id/vertical reference/reference label/visible; optional active polygon GIS layer id/numeric height field id/visible; camera EPSG:4326 lon/lat, zoom 0..22, bearing -180..180, pitch 0..75. Model and scene DEM reference must match exactly. GIS footprint uses live source geometry/height field (not a snapshot of GIS features); server validates active source/layer/schema field and raster existence when saving and opening. If source deleted/retired, retain history but fail open instead of silently substitute. Missing visible GIS layer in client must be enabled first.
- UX: in 3D use named scene panel to save actual view and per-layer flags; unsaved/changed model placement must be saved first. Open historical/latest scene from GIS, resolve pinned assets sequentially and verify size/hash/budget, then apply complete configuration atomically. DEM acknowledgment required again before entering 3D. Retain exact saved view and visibility on activation. No unsaved scene editing via public links, delete, replace, or persistence of transient selection. Native extrusion overlap and 3D Tiles limits from T015 remain unchanged.
- Acceptance: real disposable PostGIS migration through 0031, active GIS numeric field plus actual DEM and two model assets, create/revise scene, stale version denied, previous model placement resolves after new model revision, shared member reads, restricted/outsider denied, invalid camera/duplicate/missing/datum/field checks. Browser captures 3D camera/layer flags, saves versions, reloads old scene after model revision, restores camera/visibility, revocation tears down. Full convergence remains a separate release gate.
- Recovery: additive migration; revert application without dropping saved history. Any destructive downgrade requires prior backup/export and separate approval. No production deployment or main merge from candidate.
