# Project model vault and versioned placement (T014)

## Requirement, plan and acceptance
A project member should be able to save a model once, reopen it from another session, change its placement with optimistic concurrency, inspect prior placements and recover original bytes. A CAD-imported GIS feature is a valid anchor through the existing version/handle provenance; no native CAD writeback. One selected model is displayed per scene for this slice. No deletion or file replacement.
- Constitution: Core-reusable, scoped organization/project and unrestricted human access, RLS, project edit for writes, CSRF, immutable rows and audit, explicit CRS/elevation reference, GLB/GLTF portable download. No new dependency or external processing.
- Storage decision: reuse established bounded transactional PostgreSQL bytea pattern (raster), not a new service. Asset bytes immutable; placement rows do not copy bytes. Project limit 100 assets and 100 MiB, 10 MiB each, 50 placement revisions. Advisory project lock serializes quota/version writes. Consider object store/3D Tiles only for larger files or multi-model scene budgets.
- API base /api/v1/organizations/{org}/projects/{project}/3d/models: GET latest catalog; POST multipart file and placement JSON; GET {id}/download; GET {id}/placements history; POST {id}/placements with expected_version. Profile contains source_id/feature_id, scale, rotation_deg, offset_m, optional dem_id, vertical_reference and reference_label. Invalid/missing reference rejected. No public serving; downloads attachment, no-store, SHA-256 verified. Server validates bounded GLB/GLTF envelope; actual supported geometry validated by bounded static browser parser (no external URI loads).
- Anchor computed server-side from bbox centre of the current active reference feature, explicit EPSG:4326 or EPSG:3857 inverse only. The chosen source revision and fixed WGS84 longitude/latitude are stored; reopening a saved version does not silently move if GIS changes. Saving a new revision recomputes from the current feature. Original source link may become historical if GIS is changed/deleted; placement remains fixed. No inferred VN-2000 datum op. Source geometry and DEM are not modified. DEM is a reference by immutable raster ID: reopen requires explicit confirmation; removed DEM cannot be used. Relative offset in metres, not certified absolute height.
- Acceptance: fresh migration, real CAD-derived GIS anchor with independently calculated coordinates, exact downloaded bytes, distinct revisions, stale-write rejection, actor and scope checks, positive same-project sharing, restricted and outsider denial, reject external URI/missing feature/DEM and invalid units/scale. Real browser saves and reopens after reload using a fixture API, checks original vs revised parameters, renders 3D and revokes access; production gates still required.
- Recovery: additive migration with no existing row changes. Keep data/migration in place when rolling application backward; destructive downgrade drops only new tables, requires explicit backup/export and approval before use. No production operation in this candidate.
