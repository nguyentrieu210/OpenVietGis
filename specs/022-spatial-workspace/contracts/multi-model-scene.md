# Multi-model 3D scene and selection (T015)

## Requirement and plan
Users must compose one bounded 3D view of multiple versioned project models, GIS footprints and DEM, independently show/hide each layer, click a model and navigate to its linked GIS source. File assets, placement revisions and access remain governed by T014; no data/schema migration in this slice. Scene composition and visibility are per session, not shared saved scene definitions.
- Constitution check: existing scoped immutable catalog and authenticated downloads; no external URI/network or new provider. Source identity maps to existing GIS key, only if current project read and row is visible; no new writeback. Explicit DEM ID/vertical datum match; no inferred datum conversion. Stable versioned file placement retained; model ID deduplicates scene instances, one placement version per asset. Editor draft overrides pinned same asset; explicit pin restores published version. Original file export unchanged.
- Budget: at most 8 models, 100,000 triangles each, 250,000 model triangles total; existing 10 MiB per file, parser limits and DEM grid cap unchanged. Sequential authenticated fetch, SHA-256/byte-size verified. Aggregate budget enforced before renderer creation. GPU buffers/material per model; no global cache, dispose all on permission/scope/mode change.
- Placement: a shared scene uses one DEM and exact user-declared reference (or flat local zero). Reject incompatible pinned model profiles, absent source for local drafts, outside DEM/NoData anchors; never silently convert. Saved model may be viewed at its historical fixed position even if GIS source row is not currently visible. Click identifies exact model ID, highlights it and selects linked GIS row if available. A GIS-to-CAD source link remains via existing provenance.
- Rendering: same MapLibre canvas/context, one custom mesh layer per model; DEM layer and GIS footprint group have controls. Hidden custom meshes skip draw and hit test; hidden footprints use native visibility. Screen-space triangle intersection uses last render projection, nearest model depth; visible DEM mesh can occlude a model. Native extrusion-depth compositing is not part of custom CPU picking; hide the GIS extrusion group for unambiguous custom model picking on overlaps. Near-plane crossing triangles are skipped rather than approximated. No BIM editing, shared named scene persistence, LOD or 3D Tiles.
- Acceptance: count/triangle budget and clip-space depth unit tests; actual two-color WebGL pixel/triangle pick, highlight, hide/show, hidden mesh cannot pick, disposal and no external requests; prior standalone terrain and footprint pick regressions. Integrated browser must add second saved model, reject different DEM reference, toggle layers, click project source, navigate back to GIS and revoke access. No deployment or production changes; application rollback is code-only.
