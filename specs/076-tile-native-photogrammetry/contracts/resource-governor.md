# Resource governor v2
Per job budgets: host_commit_bytes, device_bytes per GPU, scratch_reserved_bytes, output_reserved_bytes, CPU slots, I/O concurrency, wall timeout; aggregate includes descendants and app/OS reserve. Example 8 GB physical reference: reserve at least 2.5 GiB OS/app, cap worker tree at 4 GiB where enforceable, leave remaining headroom; adapt after measured OS pressure. 16/32 GB profiles defined W01. UMA accounts physical CPU/GPU jointly, not additive independent budgets. Record physical bytes vs commit/RSS semantics.

Windows job object process-tree limit and Linux cgroup v2 memory.max when permitted; prove actual enforcement. macOS watchdog/resource controls evaluated separately; do not claim hard RSS enforcement if unsupported. GPU hard limits depend on provider/backend: reserve estimated bytes, observe actual allocation, isolate process and cancel at pressure; no universal hardware VRAM quota claim. Disk reservations count scratch and output and retained artifacts; low-water mark at least max(5 GiB, 10% volume) configurable and validated before admission. Fail safe if impossible. Provider that cannot bound memory is blocked in strict Lite mode.

On pressure: reduce concurrency → adjust batch/core size within same quality → retry at most twice for classified transient resource errors → block with explanation. Changing image resolution, source count or precision beyond frozen profile requires explicit approval and new quality profile. Never silently downgrade survey quality. Record actual peaks, throttling and retries. Fault inject worker allocation overflow, shared-memory pressure, disk full, cancel, OS termination. Previous manifest remains readable.
