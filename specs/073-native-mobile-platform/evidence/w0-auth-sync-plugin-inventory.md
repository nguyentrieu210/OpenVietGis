Source inspection only. No production auth or registry modification. Routes below are relative to /api/v1; exact OpenAPI coverage and real isolated PostGIS tests remain required.
## Identity and sync
- identity.rs: GET /me, /me/organizations, /auth/login/{provider}, /auth/callback/{provider}, /auth/csrf. HumanSession explicitly rejects Bearer before cookie lookup; checks revoked/expired session. No dedicated human-mobile token exchange demonstrated. edit_auth.rs and extensions/mod.rs route Bearer to organization-scoped authenticate_service. Keep browser CSRF and service token precedence; do not introduce generic fallback. Mobile auth remains blocked until distinct public-client PKCE code/session family, redirect/issuer, rotation/revocation and per-route actor authorization are independently tested.
- managed_sync.rs: base /organizations/{organization_id}/projects/{project_id}/integration-hub/managed. GET/POST /sessions, GET/DELETE /sessions/{session_id}, GET /bootstrap, /delta, /commits/{operation_id}, /events; POST /commits. Existing request CommitBody session_id/source_id UUID, base_content_revision string length 64, optional base_schema_revision length 64, operation_id <=128, optional summary <=500, allow_deletes default false, 1..1000 operations. Delta cursor integer 0..i64::MAX, limit 1..500 default 200. Scope opens before domain transaction; finish commits before response. Unknown ACK must query receipt. Existing field_offline.rs package lease is not proof of the signed mobile protected-data lease contract.
- Existing SDK packages/client-sdk/src/{auth,managed-sync}.ts, generated auth-session.ts; managed-sync SDK exports session list/revoke and desktop commands, not all mobile delta/receipt bindings. Source of truth SPEC 029 and actual server.
## Registry and signing
- extensions/manifests.rs: GET/POST /organizations/{organization_id}/extensions/manifests; GET /official; POST /official/{extension_key}/register under same org prefix.
- extensions/activations.rs: project extension base /organizations/{organization_id}/projects/{project_id}/extensions; GET/POST /activations, POST /{extension_key}/disable, POST /activations/{activation_id}/deactivate and /transition, GET /activations/{activation_id}/history. Activation binds manifest UUID; transition validates expected/target manifest IDs.
- extensions/marketplace.rs: GET /marketplace/catalog (no-store); POST /organizations/{organization_id}/marketplace/install/{publisher_id}/{extension_key}/{version}, scoped auth and CSRF. Signed reviewed catalog existing.
- extensions/validation.rs validates marketplace v1 schema, strict exactly ten manifest fields, canonical sorted JSON and Ed25519 standard base64 (32-byte key and 64-byte signature). packages/plugin-sdk/marketplace_sign.py canonicalizes UTF-8, sorted keys, compact separators and rejects NaN. Preserve byte semantics and existing v1 schema. Mobile v2 needs separate signed envelope linked to v1 digest, asset digests, capability and scoped broker; no new marketplace. Test vectors must cover non-ASCII, number representation and tamper, not assert v1 canonicalization equals RFC8785.
