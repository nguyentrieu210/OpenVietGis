# Plugin host / manifest v2 — proposal
E11/E14. Existing manifest exact 10 fields and signed catalog v1 stay unchanged. Add separately versioned mobile contribution envelope linked to exact existing manifest ID/key/version and digest; v1 Web clients never receive incompatible top-level fields. W0 confirm storage/validator/route inventory; versioned API/media type or additive separate endpoint only after review. Do not permit v1 signatures to authorize v2 assets.
## Release envelope
schema_version=2, publisher_id, extension_key, version, manifest_digest, host_api_range, platforms, capabilities/permissions, contribution_digest, assets[{id,media_type,size,sha256}], issued_at, key_id. Publisher signs deterministic canonical JSON (RFC 8785 candidate; test cross-language bytes); operator signs reviewed release/catalog. Use immutable content-addressed asset bundles, verify each digest before parsing; no mutable remote URL trust. Trust roots from approved server/operator, pinned by server identity; key rotation with reviewed cross-signed/updated catalog, deny revoked keys/releases and stale activation. Monotonic catalog epoch; offline grace bounded by lease, no silent rollback. Signed metadata alone is insufficient.
## Declarative runtime
Allowed slots workspace/map_tool/form/dashboard; typed widget allowlist (text/number/date/select/table/form/map tool), no script, HTML injection, arbitrary network URL, native code or dynamic Dart. Proposed caps: 256 KiB envelope, 500 nodes, depth 16, 32 actions, 10 MiB total assets, bounded image dimensions; action queue 8 and timeout 30s; actual lower platform limits negotiated. Validate schema before rendering. Unknown critical fields/capabilities denied. 
Action descriptor: id, command_id, typed input/output schema, required capability, permission, resource scope, online/offline mode, consent class, timeout. Broker binds active manifest + session + project to request, validates input and current permission at execution, routes only approved Core commands or scoped server calls, sanitizes result. No direct DB, raw token, FFI pointer, arbitrary network/file/device calls. GPS/camera/storage and data mutations mediated by trusted host; explicit consent per sensitive operation; no escalation from plugin UI or manifest. UI and action state disposed on close, project switch, revoke; cancel jobs and subscriptions; preserve Core data. Official compiled-in modules separately reviewed, no partner code loading.
## Platform and commerce
Android/iOS capabilities advertised separately; iOS review before any interpreted/native device bridge or purchase flow. WASM runtime optional research only, not production. Entitlement server-issued per org/plugin/version, separate from permission; never substitute license for data access. Disable hides module but authorized data/export remains; paid checkout, settlement and store compliance separate approved scope. 
Acceptance: v1 web golden signatures unchanged, v2 canonical signature vectors JS/Rust/Dart, tampered assets, key rotation/revocation, malformed graph, cross-project/permission/consent, action overflow and timeout, two reference plugins, same server registry and no domain imports in Core.
