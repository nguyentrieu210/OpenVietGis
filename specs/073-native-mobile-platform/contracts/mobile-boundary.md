# Mobile boundary overview v2 (design proposal)
Canonical existing API/schema remains authoritative. Detailed Revision 2 contracts supersede illustrative fields in this overview: [kernel](portable-kernel-contract.md), [auth](mobile-auth-contract.md), [offline](offline-sync-contract.md), [plugin](plugin-runtime-contract.md), [render](mobile-render-contract.md), [build](native-build-contract.md). Inventory current actual routes before implementing; do not invent public routes. All additive fields versioned; older web clients unaffected.

## Native FFI
Opaque EngineSession/Workspace/Layer/Job handles with explicit dispose, scope validation and bounded lifecycle; typed Result {code,message,retriable,details_redacted}; async operations with cancellation token; no raw pointers from plugins, no panic crossing FFI. Native bulk reads return batches with revision, CRS, geometry encoding and ownership/release contract; bounded page bytes/count and stale result cancellation. GeoArrow optional if verified; default bounded WKB/typed buffers. Render preview events distinct from persisted edit commands.
Operations: openWorkspace, listCapabilities, importSource, queryViewport, applyChangeSet, exportSource, transform, runProcessing, cancelJob, closeWorkspace. Names illustrative until binding generation; contract tests validate semantic parity.

## Network
Generated Dart bindings from existing OpenAPI. Explicit server identity and TLS; mobile human auth via approved OIDC PKCE flow; refresh/revoke, no baked secrets. Use existing project/layer/edit/processing/field/managed-sync and extension endpoints. Managed writes require revision, operation ID, explicit scope and server authorization; 409 conflict -> fetch scoped diff + user resolution; 401 refresh or lock; 403 lock/stop; 429 backoff; 5xx retry bounded; unknown receipt status queried before replay. Never downgrade auth.
 
## Plugin contribution (illustrative additive schema)
Existing manifest identity/version/signature and registry activation required. Mobile v2 uses separately signed versioned envelope linked to the exact v1 manifest; no incompatible top-level additions to v1. Proposed mobile contribution fields: platform=mobile; schema_version=1; slot=workspace|map_tool|form|dashboard; id; command_id (registered allowlist); required_capabilities; required_permissions; declarative_ui; asset_digest; min_host_version. JSON schema strict limits: max 256 KiB manifest including contributions, 500 UI nodes, depth 16, 32 actions, bounded strings and no script/external arbitrary URL. Limits proposed, reconcile with existing server validator before publication. Mobile host denies unknown critical fields, unsupported capabilities, stale activation or invalid signature. No raw bearer tokens, DB access, FFI, arbitrary code or unrestricted file/network/device access. UI action -> capability broker -> scoped Core or server API; explicit confirmation for sensitive writes/location/photos. Cleanup contributions, tasks, overlays and subscriptions on close/revoke.
 
## Offline and permissions
Mandatory protected-data offline lease: signed subject/server/org/project/revision/capabilities/issued/expiry, key ID and replay protections; server verifies all on reconnect. Fail closed when untrusted time or expiry. Offline data must not impersonate current live permission. Protect encryption keys via OS keystore; separate local mode and managed scope.
 
## Compatibility
Capability registry exposes available runtime, driver read/write, geometry/CRS, offline/online and restrictions. SDK and app fail safe on unsupported contract version. Reference fixtures and error codes documented; version bump only when breaking contract, with migration/compatibility plan.
