# OSM Vietnam isolated provider infrastructure
Use a dedicated build/provider host; do not build indexes on production or the current shared VPS with low free memory. Initial conservative admission: 12 GiB free memory, 60 GiB free disk; size and benchmark before enabling production. No public provider ports.
1. Obtain a dated Vietnam PBF using fetch-snapshot.sh; verify upstream MD5 then record SHA256. The failed resumed download is not a validated artifact.
2. Pin all three container images by digest. Obtain the official Photon 1.3.0 release JAR and verify SHA256 a89707c0045e4800e132e68e108d998709f48b6c94b98a6e281f571a5. Use a new private directory per dataset for each service; don't reuse active data. Set the compose variables via a restricted env file, generate a unique Nominatim password, export for preflight. Avoid printing secrets; Photon 1.3 passes password only in its isolated import container, never publish its process list. Upgrade to pgpass-capable version once verified.
3. Run preflight.sh, then docker compose up -d nominatim. Wait for successful local /search?format=jsonv2&q=Hanoi and verify PostgreSQL private network access; check database user rights and ensure the placex(country_code) index exists before running photon-import. No replication during build.
4. docker compose --profile import run --rm photon-import; after exit 0 run docker compose --profile serve up -d photon. Import deletes existing indexes: always require a fresh version directory.
5. Copy verified PBF into new VALHALLA_DATA_DIR as vietnam.osm.pbf; docker compose --profile route up -d valhalla. Use sequential import/graph builds rather than concurrent memory-intensive jobs.
6. python3 smoke.py. Record the dataset date, images, checksums, latency and result evidence. Only after qualification link private providers to API through operator-configured origins; never expose ports or PostgreSQL publicly. Loopback ports are for staging; production requires private network or authenticated tunnel and approval.
7. Refresh by building a new version, running smoke/benchmark, then switching origins with prior snapshot retained for rollback. Never replace current index in-place.
