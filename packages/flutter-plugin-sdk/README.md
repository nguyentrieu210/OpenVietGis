# OpenVietGIS Flutter Plugin SDK (candidate)
Declarative mobile contributions only; no dynamic Dart, JavaScript, HTML, native code or direct database access. Existing v1 registry remains authoritative; separately signed v2 release binds manifest ID/digest, host API range, platform, capabilities, permissions and immutable assets. Operator review binds exact publisher key, release digest, server instance, epoch and expiry. Caller must obtain trust roots, persisted epoch/revocation, activation and lease from trusted host. No bundled signing secrets.
 
Quickstart: run `node tools/new_plugin.mjs demo inspection /tmp/ovg-inspection`; edit contribution.json; register existing v1 manifest via registry; obtain signatures with separate operator approval. Run `dart pub get && dart test` in this SDK to exercise independently signed test vectors. The runtime is not a production plugin installer.
 
Supported slots: workspace/map_tool/form/dashboard. Typed nodes: text, input_text, input_number, input_date, select, table, form, map_tool. Renderer and rich node options still require qualification. Runtime bounds 500 nodes, depth 16, 32 actions, queue 8, action timeout max 30 seconds. Allowed capabilities data.read, data.edit, gps.read, camera.capture, module.read, module.edit, module.review. Mutation/device access needs explicit consent and a trusted handler with exact matching schema. Cancellation must be enforced by handlers before side effects. Never retry uncertain mutations; reconcile server receipt.
 
Canonical signing profile: sorted ASCII token object keys, UTF-8 strings without C0/C1 controls, safe integer JSON numbers only. Reject floats rather than claim full RFC8785 equivalence. No arbitrary URLs, executable assets, image decoder support, token access or commerce. Current assets limited to JSON/plain text. Golden fixture was signed independently by Python Ed25519; fixture seeds are public testing only. Host SDK must never embed those keys in production.
